# google-voice-ws

Unofficial client for Google Voice's internal web API. Send and receive SMS/MMS, list threads, and download attachments by replaying an authenticated browser session — no public API key required.

> **Unofficial**: this targets Google Voice's internal, undocumented endpoints. It relies on session cookies from a real logged-in browser and can break if Google changes internals. Use only with accounts you control.

## Features

- **Send single & MMS messages** (`sendMessage`)
- **Read threads & events** (`listThreads`) — plaintext SMS bodies, MMS metadata, direction, timestamps
- **Download attachments** (`downloadAttachment`) — images and video, multiple size variants
- **SAPISIDHASH auth** — fresh per-request signing from your session cookie (no OAuth needed)
- **Automatic cookie refresh** — pull your live session from a browser profile or a headless Playwright login

## Install

```bash
bun add google-voice-ws
```

## Quick start

```ts
import { GoogleVoiceClient, loadEnv } from "google-voice-ws";

const client = new GoogleVoiceClient(loadEnv());

// Send a text message
await client.sendMessage("t.+15551234567", "Hello from google-voice-ws", String(Date.now()), {
  tokens: { attestationToken, recaptchaToken }, // see auth notes below
});

// Read threads
const threads = await client.listThreads();
for (const t of threads) {
  for (const event of t.events) {
    console.log(`[${event.direction}] ${event.otherPartyNumber}: ${event.text}`);
  }
}
```

## Authentication

Google Voice's web client authenticates with `SAPISIDHASH`, a SHA-1-based scheme signed with your `SAPISID` cookie — not an OAuth token. Set up a session in `.env`:

```bash
cp .env.example .env
```

Then populate `GV_COOKIE` with the full `Cookie` header from an authenticated `voice.google.com` session (DevTools → Network → any request to `clients6.google.com` → Request Headers → Cookie).

### Refresh the cookie automatically

`SIDCC` cookies expire in minutes-to-hours, but browsers renew them in the background. Two ways to keep `.env` fresh:

```bash
# 1. Reuse your existing browser session (Firefox-family via cookies.sqlite;
#    Chromium-family/Safari need the optional @mherod/get-cookie peer)
bun add @mherod/get-cookie
bun run refresh-cookies

# 2. Headless Playwright login (one-time interactive login, then cron-able)
bun add playwright && bun x playwright install chromium
bun run refresh-cookies --source browser
```

The CLI verifies the refreshed cookie against the live API before writing it, and falls back to the Playwright path if the browser jar is stale. See `--help` for browser targets (`--browser chrome|brave|vivaldi|firefox|...`).

### Sending is gated by an anti-abuse token

Real sends also require two tokens Google's web client mints via its WAA/BotGuard + reCAPTCHA flow — they aren't generated by this library. Pass them to `sendMessage` as `options.tokens`:

```ts
await client.sendMessage(threadId, text, tmpId, {
  tokens: { attestationToken, recaptchaToken },
});
```

Replay a token pair from a recent capture (they're session-recent, not message-bound — replaying with different text works for a short window), or obtain fresh ones via the browser refresh flow.

## API

| Function | Description |
|----------|-------------|
| `GoogleVoiceClient.sendMessage(threadId, text, tmpId, opts?)` | Send an SMS/MMS (photo via `opts.attachment`) |
| `GoogleVoiceClient.listThreads()` | List all threads + events |
| `GoogleVoiceClient.downloadAttachment(id, sizeCode?)` | Fetch attachment bytes |
| `readBrowserSession(browser?)` | Pull a session from an installed browser |
| `refreshCookies(opts?)` | Headless Playwright session refresh |
| `loadEnv()` / `writeEnvCookie()` | Read/write `.env` credentials |

## Notable internals

- **MMS events**: `api2thread/list` puts a fixed `"MMS Sent"`/`"MMS Received"` label at event index 9 and the real content (caption + attachments) at index 14. Video attachments carry `null` size variants.
- **Attachment size**: an ~11 MB request was server-rejected; the library caps outgoing attachments at 1 MB by default with a `sharp`-based JPEG recompression fallback (`opts.compress`).
